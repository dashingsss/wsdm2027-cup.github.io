About the Challenge

Agents often solve tasks that share useful procedures. A previous search can suggest how to connect evidence in a new question; a previous shopping session can demonstrate which product requirements to check. Instruction trajectories provide a searchable source of this experience.

Agentic Search over Instruction Trajectories studies how to retrieve, combine, and adapt historical experience to support agent planning. A participant method receives the task goal, current observation, available actions, and interaction history. It returns guidance before the agent selects its next action.

The challenge covers ALFWorld, WebShop, and HotpotQA. All methods use the same agent framework, designated model configuration, and environment tools. Methods may build and reuse indexes over the public trajectory corpus within each domain.

Task description

Before each model call, your method receives the current task, observation, available actions, and interaction history. It can retrieve, combine, or summarize historical experience and return guidance. The fixed agent uses that guidance to choose its next action; the environment executes the action and returns a new observation.

Step 1

Current task

The goal, the observations so far and the actions still available to the agent.

Your method Step 2 · retrieve and adapt

Retrieve and adapt historical experience

Your method retrieves relevant historical trajectories and may combine, summarize or adapt them into guidance for the current task. This is the only step a submission controls.

Step 3

Add the guidance to the prompt

The official agent adds the guidance returned by your method to its current context before choosing the next action.

Datasets

The public release provides 1,000 trajectories and 50 development tasks per domain. Development tasks are separate from the trajectory corpus.

  • ALFWorld: household tasks in a text environment, such as finding objects, heating or cleaning them, and placing them in a target location.
  • WebShop: shopping tasks that require searching for products, checking requirements, selecting options, and completing a purchase.
  • HotpotQA: multi-hop questions that require searching documents and connecting evidence to produce an answer.

The released trajectory corpus will also be provided during hidden-test evaluation. Participants may collect or generate additional trajectories for training and local experimentation.

The development set is a curated selection covering different task types and difficulty levels. The hidden test set is designed to include more challenging tasks and new combinations of difficulties. Participants are encouraged to create additional tasks of varying difficulty to evaluate their methods.

Trajectories include a task goal, an initial observation, actions, the observations returned after those actions, stored as action/observation pairs.

Download trajectories and development tasks: huggingface.co/datasets/agentic-search-review-team/agentic-search

The dataset is gated: sign in with a Hugging Face account and request access, which is approved automatically. It ships as data-resources.zip (about 5.6 GB) with a matching SHA256SUMS. The download steps in the starter kit README cover fetching, verifying and unpacking it.

Evaluation and Baselines

The overall score gives equal weight to the three domains. Each domain score is averaged over its tasks:

  • ALFWorld: task success, scored as 0 or 1.
  • WebShop: the environment reward, ranging from 0 to 1.
  • HotpotQA: answer accuracy, scored as 0 or 1.

Overall score = (ALFWorld success rate + WebShop mean reward + HotpotQA accuracy) / 3

The organizer evaluates the three datasets sequentially and averages their three mean scores. If two teams obtain the same mean score, the team with the smaller standard deviation across the three domain scores is ranked higher.

Validation baseline results

The three retrieval baselines differ only in how they select a reference trajectory; No Retrieval is shown as the no-reference floor.

  • Random samples one trajectory uniformly at random, without reading the task text, and reuses it for the entire episode. It isolates how much the agent gains from seeing any worked example at all.
  • BM25 ranks trajectories by sparse lexical overlap with the task instruction and initial observation, using BM25Okapi over lowercased alphanumeric tokens. It retrieves the lexically closest trajectory once per task.
  • Dense Static encodes the instruction and initial observation with BGE-small-en-v1.5 on CPU and retrieves the trajectory with the highest cosine similarity, capturing semantic rather than exact-word overlap.

Participation

Registration Form

Register your team before Feb 5, 2027. Registration opens on Nov 18, 2026.

Open the registration form

All submissions are evaluated using the same organizer-controlled agent, model configuration, tools, and execution limits. Participants develop methods for retrieving and using historical trajectories. The starter kit currently uses Qwen3.5-9B; see the installation guide for local setup.

  1. Register. Submit the registration form above. Registration closes on Feb 5, 2027, the same day as the submission deadline.
  2. Install the starter kit and run a baseline. Follow the installation guide to download the data, build both images and run a baseline. The starter kit provides the runtime and four baselines; download the trajectory corpora, development tasks and environment resources separately. One command starts the official and algorithm containers together. The starter runtime defaults to 300 seconds per task, 50 actions and 50 model calls. Methods may combine multiple references; the retrieval baselines use one by default.
  3. Implement your method with a Docker image. Write your method in algorithms/methods/, rebuild your algorithm image (docker/), and evaluate it on the development tasks. The algorithm runs on CPU, with model files prepared in the image for offline use.
  4. Export the image and submit it. Submit the exported algorithm image (algorithm-image.tar), matching source code and Docker build files. Include a README with the image tag, method path (such as algorithms/methods/my_method.py) and any additional model details. See the submission checklist. Do not submit API keys or benchmark data. The submission deadline is Feb 5, 2027; interim scores are published on Jan 5, 2027.
